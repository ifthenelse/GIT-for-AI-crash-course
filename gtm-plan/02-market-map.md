Sources used: official public websites and repositories, confirmed snapshot, and

## Executive summary

Visualization, simulation, and learning through levels are already recognizable
promises. LearnGitBranching connects commands and a graph in the browser;
Oh My Git! uses a game with real Git. GitHub Skills provides exercises in actual
repositories. Microsoft Learn and Pro Git cover concepts and workflows through
learning paths and documentation.

The direction to test is connecting Git's behavior to collaboration outcomes:
follow the same incident from an edited file to a PR, policies, and recovery.
The four windows can support this path; their presence does not demonstrate an
educational advantage.

This research identifies hypotheses, not a proven unoccupied market position.
The product is not yet implemented and learning evidence is unavailable.

## Market definition

Learn to choose and explain a safe Git action, then collaborate on GitHub or
Azure DevOps. Observed categories: visual simulator, educational game, practice
on a real platform, and technical reference. Help from a colleague, just-in-time
instructions, and postponing study are plausible alternatives, still to be tested.

## Three-layer map

- Direct: LearnGitBranching and Oh My Git!, Git practice with interactive representations.
- Category: GitHub Skills, Microsoft Learn/Azure Repos, and Pro Git, addressing the same need through real practice or structured explanations.
- Alternatives to the category: informal mentoring, researching a problem, automated suggestions, and copied procedures. Their frequency is unknown.

## Priority competitor analysis

### LearnGitBranching

Category: visualizer, sandbox, and tutorial for understanding Git through its
graph. Stated audience: beginner and intermediate developers. Mechanism:
commands update the tree, with levels, undo, and git golf. The site explicitly
simulates a repository: evaluate transfer to real work separately, without
inferring that it is not taught.
Sources: [website](https://learngitbranching.js.org/), [README](https://github.com/pcottle/learnGitBranching).

### Oh My Git!

Category: open-source game for learning Git. Audience: newcomers and curious or
advanced participants. Mechanism: visualized structures, introductory cards, and
a terminal with real Git; the presentation includes remotes and collaboration.
The advertised experience requires a desktop download, and maintainers state
that maintenance is limited. These are observable conditions, not evidence of
inferior educational quality.
Sources: [website](https://ohmygit.org/), [repository](https://github.com/git-learning-game/oh-my-git).

### GitHub Skills

Promise: learn GitHub using GitHub. Audience: beginners and experts; the
introduction names new developers and students. Mechanism: a personal project
copy, instructions, and feedback through Issues and Actions. The introduction
runs in the participant's repository and depends on the real GitHub workflow.
The former Skills domain redirects to GitHub Learn.
Sources: [organization](https://github.com/skills), [introduction](https://github.com/skills/introduction-to-github).

### Microsoft Learn and Azure Repos

Category: guided training and product documentation. The Git module identifies
beginners, developers, and students, with objectives, an exercise, and assessment.
Azure Repos documents collaboration, PRs, and policies. The introductory module
lists a GitHub account, CLI familiarity, and an editor as prerequisites. Module
and documentation are separate resources: their combined effect on the learner
needs evaluation.
Sources: [Git module](https://learn.microsoft.com/en-us/training/modules/intro-to-git/),
[Azure Repos](https://learn.microsoft.com/en-us/azure/devops/repos/git/?view=azure-devops).

### Pro Git

Category: complete online book. Apparent audience: readers seeking progressive
explanations and deeper understanding. Chapters extend from installation and
basics to workflows, GitHub, tools, and internals. The Italian page lists the
translation among those started and shows Italian and English headings; this
is not a judgment on the entire body of content.
Sources: [English](https://git-scm.com/book/en/v2), [Italian](https://git-scm.com/book/it/v2).

## Positioning map

Qualitative axes, not measured market coordinates:

1. Controlled simulation versus real practice: LearnGitBranching and GitHub
   Skills show the two ends; Oh My Git! combines visualization with real Git.
2. Mental model versus platform collaboration: graph visualization and
   GitHub/Azure workflows are distinct emphases in the sources.
3. Guided exercise versus in-depth reference: games/Skills and books/documentation
   offer different ways of learning.

The new course occupies a designed rather than demonstrated position: guided
simulation connecting Git with collaboration, complete in Italian and English.

**[GAP HYPOTHESIS] One incident, from file to policy.** Relevance needs testing
with the three audiences; an unclaimed position is unproven; feasibility depends
on correct scenarios. Test: explain and complete a new workflow without guidance.

**[GAP HYPOTHESIS] Recovery explained through visible consequences.** Plausible
but unvalidated need; alternatives already cover reset/merge/recovery;
feasibility depends on simulator fidelity. Test: choose and explain a strategy
that preserves shared work.

## Category dynamics

Understanding Git through visualization and learning through real projects are
established narratives. Sources do not establish saturation, growth, or
quantitative demand. Avoid the generic promise “interactive Git” as evidence
of differentiation.

## Positioning hypotheses

1. **Visual Git collaboration lab**, the recommended direction to test.
2. Git recovery practice lab: incidents and the consequences of solutions.
3. Practical Git path in Italian and English: useful requirement, uniqueness unproven.
